# Лабораторна робота № 3 - варіант 2

Заплетнюк Євгеній Сергійович, IV курс, спеціальність «Інженерія програмного забезпечення», 2026.

Тема: практикум із розроблення через тестування, цикл Red - Green - Refactor.

Гілка `lab3-variant2` продовжує `lab2-variant2` (базовий коміт `a56e6a6`).

## Запуск

Перевірено з Node.js 24.21.0, npm 11.19.0, TypeScript 6.0.3, Vitest 5.0.3.

```sh
npm ci
npm run test:lab3
npm run coverage
npm run typecheck
npm run lint
npm run format:check
npm run demo -- sick 11 333.33
npm run demo -- parking 600 --night --weekend
```

Відповіді прикладів: `2666.64 UAH` та `80.00 UAH`. Некоректні дані завершують CLI з кодом 1.

## Контракт

- `calcParkingFee(minutes, options)` у `src/parking.ts`: невід'ємні цілі хвилини; перші 15 безкоштовні; перша година 30 грн, кожна наступна розпочата година 20 грн; обмеження 200 грн, потім нічний коефіцієнт 0.5, потім вихідний 0.8. Некоректна тривалість: `INVALID_DURATION`.
- `calcSickPay(days, dailyAverage)` у `src/sickPay.ts`: цілі дні 0-30; скінченний невід'ємний **середньоденний** заробіток у гривнях. Дні 1-5 оплачуються по 60 %, 6-10 по 80 %, 11-30 по 100 %. Округлення виконується один раз для загальної суми. Помилки: `INVALID_DAYS`, `INVALID_DAILY_AVERAGE`.

Уточнення неоднозначностей методички: нуль днів і нульовий заробіток допустимі; понад 30 днів відхиляється, без обрізання; ставки застосовуються до окремих періодів. Перевірка заробітку виконується навіть за нуля днів. Це навчальні правила, а не реалізація законодавства про лікарняні.

Обмеження: використовується `number`, без гарантії довільної десяткової точності та без підтримки надвеликих сум. Паркування, як у методичці, має одне обмеження на виклик; поділу на календарні доби немає. Окремого GUI калькулятора немає; HTML-звіт покриття відкривається через `coverage/index.html`.

## Тести та історія

Нові модулі: 70 тестів (35 + 35), разом із попередніми роботами 144. У зафіксованому запуску всі пройшли. Покриття нових модулів: 100 % рядків, гілок, функцій та операторів. CLI не входить у покриття бізнес-логіки; сім його запусків перевірено окремо.

- `evidence/tdd.json` - 13 Red, 13 Green, 8 Refactor з хешами комітів.
- `evidence/parking/`, `evidence/sickPay/` - вивід Vitest для кожного кроку.
- `evidence/coverage.txt`, `coverage-summary.json`, `final-tests.json` - фінальні результати.
- `evidence/mutations.json` - шість виявлених контрольованих помилок; початковий код відновлено.
- `evidence/cli.txt` - сім фактичних CLI-запусків із кодами завершення.
- `evidence/vectors.json` - 70 векторів таблиці звіту; повторне формування: `node tools/vectors.ts`.
- `reports/` - звіт DOCX та PDF.

В індивідуальному модулі є шість повних циклів з окремим Refactor у кожному. У показовій частині сім нових вимог починалися з Red. Приклади округлення з методички вже проходили, тому вони збережені окремим `test:`-комітом і не подані як Red.

```sh
git log --reverse --oneline origin/lab2-variant2..lab3-variant2
git show 049d18b
git show 94fdab9
git show db27a16
```

Перший Red кожного нового модуля падає через відсутній файл імпорту. Наступні Red падають на невиконаній поведінці. Всі Green і Refactor перевірено фактичним запуском. Під час перевірки старого коміту очікуваний Red означає ненульовий код тестової команди.

Рецензія у звіті спирається на наданий документ колеги та його знімки історії: репозиторій за URL із документа був недоступний, тому вміст усіх його комітів не перевірено.
