# Лабораторна робота № 1

**Тема:** Розгортання середовища автоматизації тестування. Структура проєкту та перший автоматизований тест.

**Виконавець:** Заплетнюк Євгеній Сергійович.

**Група:** 3 ІПЗ.

Потрібен Node.js 24.21.0 або сумісна новіша версія. Команди виконуються в корені репозиторію.

```sh
npm ci
npm test
npm run test:watch
npm run coverage
npm run lint
npm run typecheck
npm run format:check
```

`test:watch` працює до зупинки через `Ctrl+C`. HTML-звіт покриття: `coverage/index.html`.
Для автоматичного форматування: `npm run format`.

- `.prettierrc`, `.prettierignore` — форматування й виключення похідних файлів.
- `.gitignore` — виключення залежностей, покриття, кешу та інших артефактів.
- `package.json`, `package-lock.json` — команди та зафіксовані залежності.

Пороги покриття: рядки — 80 %, гілки — 90 %, функції — 100 %.

## Варіант 2: індекс маси тіла

`src/bmi.ts` містить `calculateBmi(weightKg, heightM)`, а `tests/bmi.test.ts` — 13 тестів цієї функції.

Формула: `weightKg / heightM ** 2`. Вага задається в кілограмах, зріст — у метрах.
Наприклад, `calculateBmi(70, 1.7)` повертає приблизно `24.2214532872` кг/м².
Функція не округлює результат; дробові значення в тестах порівнюються через `toBeCloseTo`.

Нульовий, від’ємний, нескінченний зріст і `NaN` спричиняють `INVALID_HEIGHT`.
Додаткова перевірка ваги відхиляє недодатні та нескінченні значення і `NaN` з `INVALID_WEIGHT`.
Межовий тест — зріст `0`, який має бути відхилений.

Загалом: 17 тестів у двох файлах. Покриття обох модулів — 100 % за всіма показниками.
Індивідуальне завдання оформлено в гілці `lab1-variant2`; показовий приклад — у `main`.

## Лабораторна робота № 2: модульне тестування, варіант 2

Автор: Заплетнюк Євгеній Сергійович, група 3 ІПЗ.

- `src/order.ts` - показовий модуль замовлення та функція `calcVat(total, rate)`.
- `tests/order.test.ts` - 32 тести суми, знижки, доставки та підсумку замовлення.
- `tests/vat.test.ts` - 25 тестів виділення ПДВ.

`calcVat` виділяє податок, уже включений у суму: `total * (rate / (1 + rate))`,
із округленням до копійок. Наприклад, `calcVat(1200, 0.2)` повертає `200`.
Ставка задається часткою одиниці в межах [0, 1]. Некоректна ставка,
NaN або нескінченність спричиняють `INVALID_VAT_RATE`.
Додатково некоректна, від’ємна або нескінченна сума відхиляється з `INVALID_TOTAL`.
Обчислення використовують `number` і мають обмеження двійкової точності.

Перевірено звичайні результати, округлення, межі ставок -1/0/1 та 0/1/2,
а також -0.01/0/0.01 і 0.99/1/1.01. Очікувані значення задано явно,
використано `it.each`, `toBeCloseTo` і `toThrow` із кодом помилки.

```sh
npm ci
npm test -- tests/order.test.ts tests/vat.test.ts
npm test -- tests/vat.test.ts --reporter=verbose
npm run coverage
npm run typecheck
npm run lint
npm run format:check
```

Друга лабораторна додає 57 тестів. Разом із 17 тестами першої роботи - 74 тести.
HTML-звіт покриття створюється в `coverage/index.html`.
Для поточної гілки пороги: рядки 80 %, гілки 90 %, функції 100 %.

Експеримент другої лабораторної: тимчасовий виклик `calcOrderTotal` без `expect`
збільшив набір другої роботи з 57 до 58 тестів, але покриття залишилося 100 %.
Після експерименту тест видалено. Покриття показує виконані ділянки,
але саме по собі не перевіряє правильність результату.
